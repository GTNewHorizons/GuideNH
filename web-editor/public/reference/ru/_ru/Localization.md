# Локализация

GuideNH поддерживает локализованные страницы руководств и локализованные ресурсы руководств.

## Структура папок

Локализация во время выполнения организована по папкам:

```text
config/guidenh/DefaultGuide/<modid>/guidenh/
|-- _en_us/
|   `-- index.md
`-- _zh_cn/
    `-- index.md
```

В демонстрационном resource pack репозитория сохраняется внешний слой `assets/`:

```text
wiki/resourcepack/assets/<modid>/guidenh/
|-- _en_us/
|   `-- index.md
`-- _zh_cn/
    `-- index.md
```

Языковыми корнями считаются только папки с подчёркиванием. Обычные папки `en_us/` и `zh_cn/` больше не распознаются как корни локализации.

## Порядок поиска страниц

Для каждого запрошенного идентификатора страницы GuideNH проверяет:

1. `_<current language>/<page>`
2. `_<default language>/<page>`, если страница на текущем языке отсутствует
3. `<page>` без языковой папки

Страницы руководства откатываются только к `defaultLanguage` самого руководства. Автоматически обнаруженные руководства resource pack по-прежнему используют `en_us` как значение по умолчанию, поэтому наличие другой языковой папки не делает её резервным языком.

## Переопределение страницы ключом `.lang`

Полный исходный текст страницы можно заменить значением ключа `.lang`, но только если физический файл страницы уже существует. Файл остаётся проверкой существования и источником отката.

- GuideNH сначала находит файл обычным порядком языкового отката.
- После нахождения файла GuideNH ищет локализованное для страницы значение `.lang` на запрошенном языке.
- Если ключ существует и его значение не пусто, это значение становится исходным Markdown перед разбором.
- Если ключ отсутствует или пуст, используется содержимое найденного файла.

При использовании непустого значения `.lang` GuideNH перед разбором объединяет отсутствующие поля frontmatter с найденной физической страницей. Локализованный frontmatter имеет приоритет для явно заданных полей: например, `navigation.title` остаётся переведённым, а новые структурные поля (`navigation.recommend`, `navigation.priority`, категории, ссылки на предметы, сведения об авторах и масштаб страницы) наследуются из резервного `.md`-файла. Благодаря этому старый полный перевод не теряет рекомендации главной страницы после обновления метаданных исходной страницы.

Формат ключа:

```text
guidenh.page.<namespace>.<folder>.<page path without .md>
```

Пример:

```text
assets/guidenh/guidenh/_en_us/charts.md
-> guidenh.page.guidenh.guidenh.charts
```

Разделители пути превращаются в `.`. Буквальные точки внутри сегмента экранируются, чтобы не смешиваться с разделителями сегментов:

```text
foo.bar.md -> foo_x2e_bar
```

Остальные символы, не являющиеся буквами или цифрами, экранируются тем же шаблоном `_x<hex>_`.

В значении `.lang` последовательности `\n` и `\r` преобразуются в настоящие переводы строк до разбора Markdown. Поэтому значение может содержать всю страницу: frontmatter, заголовки, списки и MDX-теги.

Правила создания:

- записывайте страницу одной физической строкой `.lang` для соответствующего ключа;
- используйте последовательность `\n`, если нужен перевод строки Markdown;
- не вставляйте настоящие переводы строк в само значение `.lang`, потому что Forge читает `.lang` построчно;
- не записывайте `\\n`, если не хотите, чтобы итоговый Markdown содержал буквальные символы `\n`.

GuideNH не создаёт страницы только из `.lang`. Настоящий файл страницы всё равно обязателен.

## Длина ключа

GuideNH не устанавливает дополнительного ограничения длины ключей страниц. В Minecraft 1.7.10 / Forge языковые данные фактически являются картой строковых свойств, поэтому практическими ограничениями остаются память и удобство сопровождения. Короткие пути проще создавать и проверять.

## Рекомендации по созданию

- задавайте `defaultLanguage` явно, если для руководства нужен неанглийский язык отката;
- добавляйте общую нейтральную страницу только тогда, когда межъязыковой откат действительно нужен;
- сначала переводите страницы, а ресурсы переводите только тогда, когда в них встроен текст;
- по возможности используйте общие пути к ресурсам вместо отдельных имён файлов для каждого языка.

## Порядок поиска ресурсов

Для ресурсов руководств используется более подробный порядок отката:

1. `_<current language>/<path>`
2. если текущий язык отличается от языка руководства по умолчанию, `_<default language>/<path>`
3. `<path>`

Это позволяет локализовать изображения и ресурсы, похожие на текстуры.

## Поиск и язык

Документы поиска хранят и исходный язык Minecraft, и язык анализатора Lucene. Если текущий язык Minecraft не сопоставлен с известным анализатором, поиск использует английскую токенизацию.

## Настройка игнорирования переводов

GuideNH не предоставляет глобального переключателя «игнорировать переводы». Чтобы руководство откатывалось к языку, отличному от английского, явно задайте для него `defaultLanguage` в коде.

## Пример

```text
config/guidenh/DefaultGuide/guidenh/guidenh/_en_us/index.md
config/guidenh/DefaultGuide/guidenh/guidenh/_zh_cn/index.md
config/guidenh/DefaultGuide/guidenh/guidenh/_en_us/test1.png
config/guidenh/DefaultGuide/guidenh/guidenh/_zh_cn/test1.png
```

Эквивалент для демонстрационного resource pack репозитория:

```text
wiki/resourcepack/assets/guidenh/guidenh/_en_us/index.md
wiki/resourcepack/assets/guidenh/guidenh/_zh_cn/index.md
wiki/resourcepack/assets/guidenh/guidenh/_en_us/test1.png
wiki/resourcepack/assets/guidenh/guidenh/_zh_cn/test1.png
```
