# Временная шкала анимации для размышлений

GuideNH поддерживает анимированные временные шкалы в стиле Ponder внутри блоков `<GameScene>`. Вы предоставляете
внешний файл JSON, который определяет ключевые кадры, движения камеры и аннотации в мире, а также
GuideNH отображает интерактивный индикатор выполнения с элементами управления воспроизведением/паузой под 3D-сценой.

## Быстрый старт

1. Создайте файл Ponder JSON и поместите его в пакет ресурсов (см. [Размещение файла](#file-placement)).
2. добавьте `<ImportPonder src="..."/>` внутри блока `<GameScene>` рядом с `<ImportStructure>`.

```mdx
<GameScene zoom="4">
  <ImportStructure src="scenes/my_machine.snbt" />
  <ImportPonder src="scenes/my_machine_ponder.json" />
</GameScene>
```

> **Примечание:** `<ImportPonder>` должен находиться внутри блока `<GameScene>`. Атрибут `src` имеет значение
> обязателен. Данные структуры по-прежнему предоставляются `<ImportStructure>` или `<ImportStructureLib>`.

## Размещение файла

Подумайте, файлы JSON следуют тем же правилам пути к пакету ресурсов, что и структуры SNBT:

```
assets/<modid>/guidebooks/
  pages/machines/my_machine.mdx       <- guide page
  pages/machines/my_machine.snbt      <- structure data
  pages/machines/my_machine.json      <- Ponder JSON
```

Атрибут `src` принимает как относительные, так и абсолютные идентификаторы:

| Пример | решено как |
|---------|-------------|
| `src="my_machine.json"` | относительно каталога текущей страницы. |
| `src="mymod:guidebooks/pages/machines/my_machine.json"` | Абсолют (пространство имен `mymod`) |

## Формат JSON

```json
{
  "totalTime": 120,
  "keyframes": [
    {
      "time": 0,
      "label": "Start",
      "camera": {
        "zoom": 2.0,
        "rotX": 25.0,
        "rotY": -30.0,
        "rotZ": 0.0,
        "offX": 0.0,
        "offY": 0.0
      },
      "layer": null,
      "annotations": []
    },
    {
      "time": 60,
      "label": "Mid-point",
      "camera": {
        "rotY": -90.0
      },
      "annotations": [
        {
          "type": "diamond",
          "x": 1.5, "y": 2.5, "z": 1.5,
          "color": "0xFFFF4444",
          "tooltip": "Input hatch",
          "alwaysOnTop": false
        }
      ]
    },
    {
      "time": 120,
      "camera": {
        "rotY": -150.0
      }
    }
  ]
}
```

### Корневые поля

| Поле | Тип | Обязательно. | Описание |
|-------|------|----------|-------------|
| `totalTime` | целое число | Да | Общая продолжительность в тиках (20 тиков = 1 секунда). Минимум ограничен 1. |
| `keyframes` | массив | Да | Список объектов ключевых кадров. Может быть пусто. |

### Поля ключевых кадров

| Поле | Тип | Обязательно. | Описание |
|-------|------|----------|-------------|
| `time` | целое число | Да | галочка, в которой происходит этот ключевой кадр (0 <= время <= общее время). |
| `hidden` | логическое значение | Нет | Когда `true`, ключевой кадр по-прежнему применяет состояние камеры/NBT/объекта/аннотации в своем `time`, но для него не отображается видимый узел на индикаторе выполнения, и видимая навигация по ключевым кадрам пропускает его. |
| `label` | строка | Нет | необязательная запасная метка, отображаемая при наведении курсора на узел ключевого кадра на индикаторе выполнения. |
| `labelKey` | строка | Нет | ключ перевода метки ключевого кадра. При разрешении он переопределяет `label`. |
| `camera` | объект | Нет | состояние камеры в этом ключевом кадре. Нулевые поля наследуются от предыдущего ключевого кадра. |
| `cameraEaseTicks` | целое число или ноль. | Нет | Сколько тактов требуется камере, чтобы перейти от **предыдущего** ключевого кадра к этому. `null` (по умолчанию) = облегчение по всему сегменту. `0` = мгновенная привязка. `N > 0` = замедлите движение на N тактов, затем удерживайте в целевом положении. |
| `layer` | целое число или ноль. | Нет | переопределение видимого слоя. `null` (или опущен) показывает все слои. Индекс на основе 1. |
| `annotations` | массив | Нет | список объектов аннотаций, отображаемых, пока этот ключевой кадр активен. |
| `sounds` | массив | Нет | Список звуков, воспроизводимых один раз, когда этот ключевой кадр становится активным во время воспроизведения вперед. |
| `particles` | массив | Нет | Список всплесков частиц или предустановок во время выполнения, которые активируются, когда этот ключевой кадр становится активным во время прямого воспроизведения. |
| `blockChanges` | массив | Нет | список замен блоков, применяемых, когда этот ключевой кадр впервые становится активным. |
| `mergeTileNBT` | массив | Нет | Объедините соединения SNBT с объектами мозаичного изображения в позициях блоков. |
| `modifyTileNBT` | массив | Нет | установите для одного пути NBT элемента плитки значение SNBT. |
| `removeTileNBT` | массив | Нет | удалить один путь NBT к объекту тайла. |
| `createEntities` | массив | Нет | Создание объектов, принадлежащих Ponder, на которые могут ссылаться последующие операции NBT с объектами. |
| `setEntityNBT` | массив | Нет | Замените NBT указанного объекта на предоставленное соединение SNBT. |
| `mergeEntityNBT` | массив | Нет | объединить соединение SNBT со ссылочным объектом. |
| `modifyEntityNBT` | массив | Нет | установите для одного пути NBT объекта, на который ссылаются, значение SNBT. |
| `removeEntityNBT` | массив | Нет | Удалите один путь NBT объекта, на который ссылаются. |
| `removeEntities` | массив | Нет | удалите один или несколько объектов, принадлежащих Ponder, с помощью `ref`, используя стабильный реестр объектов сцены. |

Скрытые ключевые кадры полезны, если вам нужны дополнительные изменения промежуточного состояния без добавления нового видимого узла.
на временную шкалу. Например, вы можете разделить несколько обновлений `modifyTileNBT` на несколько тиков, отметьте
промежуточные ключевые кадры скрыты, а на индикаторе выполнения остаются видимыми только основные доли.

### Поля камеры

Все поля камеры являются необязательными. Любое поле `null` или пропущенное поле наследует свое значение от ближайшего
предыдущий ключевой кадр, определявший его; если ни один предыдущий ключевой кадр не определил поле, используется сцена по умолчанию.
используется значение камеры.

| Поле | Тип | Описание |
|-------|------|-------------|
| `zoom` | плавающее значение | Уровень масштабирования камеры (0,1–10,0). |
| `rotX` | плавающее значение | поворот по оси X в градусах. |
| `rotY` | плавающее значение | вращение оси Y в градусах. |
| `rotZ` | плавающее значение | вращение по оси Z в градусах. |
| `offX` | плавающее значение | Смещение панорамирования по горизонтали в пикселях экрана. |
| `offY` | плавающее значение | Смещение панорамирования по вертикали в пикселях экрана. |

Камера плавно интерполирует соседние ключевые кадры с помощью кривой **ускорения/уменьшения**.
используйте `cameraEaseTicks` на ключевом кадре **назначения**, чтобы контролировать продолжительность замедления:

```json
{ "time": 60, "cameraEaseTicks": 0,  "camera": { "rotY": 90 } }   <- instant snap
{ "time": 120, "cameraEaseTicks": 20, "camera": { "rotY": 180 } }  <- ease over 20 ticks then hold
{ "time": 180, "camera": { "rotY": 270 } }                         <- ease over full segment (default)
```

## Блокировать изменения

Массив `blockChanges` в ключевом кадре заменяет блоки в живой структуре, когда этот ключевой кадр
становится активным. Это позволяет анимации показывать состояния «до» и «после», размещать или удалять
блокирует или анимирует включение машины.

```json
{
  "time": 60,
  "blockChanges": [
    { "x": 1, "y": 1, "z": 1, "block": "minecraft:lit_furnace", "meta": 4, "particles": true },
    { "x": 1, "y": 2, "z": 1, "block": "minecraft:air", "particles": false },
    {
      "x": 2, "y": 1, "z": 2, "block": "minecraft:chest", "meta": 2,
      "nbt": "{Items:[{Slot:0b,id:\"minecraft:iron_ingot\",Count:8b,Damage:0s}]}"
    }
  ]
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `x`, `y`, `z` | целое число | - | **Обязательно.** Положение изменяемого блока (координаты конструкции). |
| `block` | строка | - | **обязательный.** Имя в реестре, например `"minecraft:furnace"`. Используйте `"minecraft:air"`, чтобы удалить блок. |
| `meta` | целое число | `0` | Блокировать метаданные/значение ущерба. |
| `particles` | логическое значение | `true` | Создавать ли эффекты частиц текстуры блока, когда это изменение блока срабатывает во время прямого воспроизведения. Частицы взяты из собственной текстуры значка блока. Установите значение `false` для подавления (например, для автоматического удаления). |
| `nbt` | строка | `null` | строка SNBT для тега объекта плитки, например для сундуков, печей и т.п. Разбирается с помощью `JsonToNBT`. Ключи должны быть **без кавычек** (стандартный формат SNBT). Игнорируется, если блок не имеет элемента плитки. |

**Безопасный поиск:** При поиске назад среда выполнения восстанавливает все измененные позиции на свои места.
исходное состояние структуры, затем повторно применяются изменения с ключевых кадров с 0 по текущий.
отображаемая структура всегда правильна независимо от направления поиска.

> **Примечание о частицах:** Частицы блочной текстуры срабатывают один раз, только во время прямого воспроизведения, когда
> ключевой кадр сначала становится активным. Они очищаются при поиске, перезапуске или начальной загрузке.

## Звуки ключевых кадров

добавьте массив `sounds` к ключевому кадру, чтобы воспроизводить один или несколько сопровождающих звуков, когда ключевой кадр становится активным.
во время воспроизведения вперед. При поиске и начальной загрузке звуки ключевых кадров не воспроизводятся; перезапуск очищает
воспроизведите историю, чтобы звуки снова сработали.

```json
{
  "time": 130,
  "label": "Furnace lights up",
  "sounds": [
    { "sound": "guidenh:machine.start", "volume": 0.8 },
    { "src": "guidenh:sounds/machine/hum.ogg", "volume": 0.4, "x": 1.5, "y": 1.5, "z": 1.5 }
  ]
}
```

Звуковые поля:

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `sound` | строка | - | Идентификатор звукового события, например `guidenh:machine.start`. |
| `src` | строка | - | идентификатор или путь звукового файла; `guidenh:sounds/machine/start.ogg` становится `guidenh:machine.start`. |
| `volume` | плавающее значение | `1.0` | Громкость воспроизведения до затухания. |
| `pitch` | плавающее значение | `1.0` | Шаг воспроизведения. |
| `cooldown` | целое число | `250` | минимум миллисекунд, прежде чем тот же звук сможет воспроизвестися снова. |
| `x`, `y`, `z` | плавающее значение | нет | Необязательное положение источника в пространстве сцены для ослабления в пространстве экрана. |
| `radius` | плавающее значение | короткая сторона сцены * 0,75 | Радиус затухания в пикселях экрана. |
| `minVolume` | плавающее значение | `0.15` | Минимальный коэффициент ослабления. |

## Частицы ключевого кадра

добавьте массив `particles` к ключевому кадру, если вам нужны однократные всплески частиц или локальные на временной шкале.
наложение погоды во время прямого воспроизведения. Эти частицы не запускаются повторно во время обратного хода.
очистка и поиск/перезапуск очищают их перед воспроизведением активного состояния.

Общие частицы:

```json
{
  "time": 110,
  "particles": [
    {
      "name": "smoke",
      "x": 1.5,
      "y": 1.85,
      "z": 1.5,
      "vx": 0.0,
      "vy": 0.01,
      "vz": 0.0,
      "size": 0.18,
      "time": 16,
      "amount": 3
    }
  ]
}
```

Предварительная настройка взрыва:

```json
{
  "time": 160,
  "particles": [
    {
      "preset": "explosion",
      "x": 1.5,
      "y": 1.45,
      "z": 1.5,
      "time": 8,
      "power": 2.4
    }
  ]
}
```

Предустановка погоды:

```json
{
  "time": 220,
  "particles": [
    {
      "preset": "rain",
      "weather": "snow",
      "x": [0, 2],
      "z": [0, 2],
      "time": 100,
      "amount": 8
    }
  ]
}
```

Поля частиц:

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `preset` | строка | нет | Специальная предустановка. `explosion` вызывает вспышку/дымовой взрыв в ванильном стиле. `rain` включает настройку погоды. |
| `weather` | строка | `rain` | тип погоды, используемый `preset: "rain"`. Поддерживаемые значения: `rain`, `snow`. |
| `name` | строка | нет | Общий вид частиц. Поддерживаемые значения: `billboard`, `smoke`, `largesmoke`, `explode`, `flash`, `largeexplode`, `hugeexplosion`. |
| `particle` / `kind` | строка | нет | псевдонимы совместимости для `name`. |
| `x`, `z` | число с плавающей запятой или массив. | границы сцены | Происхождение частиц или погодные условия. Общие частицы используют скалярные координаты. Для `preset: "rain"` скалярные значения нацелены на один столбец осадков, а массивы определяют прямоугольное покрытие парами конечных точек. |
| `vx`, `vy`, `vz` | плавающее значение | `0.0` | Начальный вектор движения. `motionX/Y/Z` являются допустимыми псевдонимами. |
| `time` / `lifetime` | целое число | зависит от предустановки | Время жизни частиц в тиках. Для `preset: "rain"` это общая продолжительность погоды, включая постепенное появление и затухание. |
| `size` | плавающее значение | зависит от предустановки | Общий половинный размер частиц в блочных единицах. |
| `amount` | целое число | зависит от предустановки | Общее количество частиц. Для `explosion` опущенная сумма масштабируется от `power`. Для `preset: "rain"` это средняя плотность погоды за такт. |
| `power` | плавающее значение | `2.0` | Сила взрыва для предустановки `explosion`. |

Примечания к предустановкам погоды:

- `preset: "rain"` — это точка входа для общей предустановки погоды. Используйте `weather: "rain"` для обозначения осадков или
`weather: "snow"` для снегопада.
- этот пресет относится к погоде, принадлежащей временной шкале. Он поддерживает повторное воспроизведение, паузу, поиск и быструю перемотку вперед.
с остальной частью временной шкалы Ponder.
- Для постоянного отображения погоды в сцене за пределами временной шкалы Ponder используйте тег `<Weather>` внутри
вместо этого `<GameScene>`.
- Настройки погоды игнорируют `y`; Вертикальный диапазон появления определяется на основе границ текущей сцены.
- `x: 5, z: 8` нацелен на один столбец осадков. Массивы используют пары конечных точек:
`x: [1, 5, 10, 12], z: [2, 6, 20, 24]` создает два закрытых прямоугольника.
- Если на одной оси имеются дополнительные несовпадающие значения массива, несовпадающий хвост игнорируется.
- Среда выполнения автоматически формирует эффект с помощью короткого начального перехода и устойчивой середины.
раздел и конечный переход.
- Дождь порождает быстро падающие капли и периодические брызги на землю. Снег появляется медленнее, дрейфует
хлопья без частиц брызг.
- Погодная зона получена из текущих границ GameScene, поэтому эффект масштабируется в зависимости от
импортированная структура вместо жестко запрограммированного поля.
- один и тот же столбец `x/z` никогда не объединяет несколько типов погоды одновременно. Ранее перекрытие
объявления погоды сохраняют общие столбцы; более поздние визуализируются только на оставшейся области.

## Операции NBT с объектом плитки

используйте `mergeTileNBT`, `modifyTileNBT` и `removeTileNBT`, когда блок остается на месте, но его
изменяются данные объекта плитки. Операции безопасны при поиске: GuideNH восстанавливает исходный тайл NBT и
затем воспроизводит все операции от ключевого кадра 0 до активного ключевого кадра.

```json
{
  "time": 80,
  "mergeTileNBT": [
    {
      "x": 2, "y": 1, "z": 2,
      "nbt": "{InputTanks:[{Level:{Speed:0.25,Target:0.25,Value:0.0},TankContent:{Amount:250,FluidName:\"minecraft:lava\"}}]}"
    }
  ],
  "modifyTileNBT": [
    {
      "x": 2, "y": 1, "z": 2,
      "path": "InputTanks[0].TankContent.Amount",
      "value": "500"
    }
  ],
  "removeTileNBT": [
    { "x": 2, "y": 1, "z": 2, "path": "InputTanks[0].Level.Target" }
  ]
}
```

| Поле | Используется | Описание |
|-------|---------|-------------|
| `x`, `y`, `z` | все | Положение блока объекта тайла в координатах структуры. |
| `nbt` | `mergeTileNBT` | Соединение SNBT объединено с объектом плитки. Существующие составные ключи объединяются рекурсивно; другие значения заменяют старое значение. |
| `path` | `modifyTileNBT`, `removeTileNBT` | Пунктирный путь NBT со списком индексов, например. `Items[0].Count` или `InputTanks[0].TankContent.Amount`. |
| `value` | `modifyTileNBT` | значение SNBT, записанное в `path`, например. `3b`, `500`, `"\"text\""`, `{Count:1b,id:"minecraft:stone"}`. |

Пути следуют той же идее, что и пути Minecraft `/data`: используйте точки для составных ключей и
`[index]` для записей списка. Обход списка в настоящее время предполагает, что пройденные записи списка будут
соединения, соответствующие общим тайлам NBT, таким как инвентарь, резервуары и слоты для рецептов.

---

## Действия с объектами

Обычные теги `<Entity>` уже поддерживаются в `GameScene`. Обдумывание сроков также может создать
собственные объекты с помощью `createEntities`, затем нацеливайтесь на эти объекты с помощью `ref` в последующих ключевых кадрах.

```json
{
  "time": 0,
  "createEntities": [
    {
      "ref": "marker",
      "sceneEntityId": "marker",
      "id": "minecraft:pig",
      "x": 1.5, "y": 1.0, "z": 2.5,
      "yaw": 180,
      "nbt": "{CustomName:\"Before\",CustomNameVisible:1b}"
    }
  ]
}
```

| Поле | Описание |
|-------|-------------|
| `ref` | необходимое локальное имя ссылки для последующих операций. |
| `sceneEntityId` | Необязательный стабильный локальный идентификатор сцены, используемый для отношений монтирования, безопасной для воспроизведения замены, восстановления импорта/экспорта и любого последующего удаления этого логического объекта. По умолчанию используется внутренний идентификатор, полученный из `ref`. |
| `id` | идентификатор объекта, например. `minecraft:pig`, `Pig` или идентификатор объекта мода, поддерживаемый загрузчиком объекта сцены. |
| `x`, `y`, `z` | Необязательная позиция появления. По умолчанию используется `0, 0, 0`, если только `nbt` не предоставляет `Pos`. |
| `yaw`, `pitch` | Необязательная ротация появления. По умолчанию используется `0, 0`, если только `nbt` не предоставляет `Rotation`. |
| `bodyYaw`, `headYaw` | Дополнительные переопределения отклонения тела/головы живого существа. Если этот параметр опущен при наличии `yaw`, они следуют за `yaw`. |
| `nbt` | Необязательное соединение SNBT, применяемое при создании объекта. |
| `name`, `uuid` | Необязательные поля профиля проигрывателя предварительного просмотра при создании объекта проигрывателя предварительного просмотра. |
| `mount` | дополнительный стабильный `sceneEntityId` транспортного средства, на котором этот объект должен ездить после создания или последующего воспроизведения. |
| `unmount` | Необязательное логическое значение, которое очищает текущее стабильное отношение монтирования объекта перед применением любого последующего `mount`. |

После создания используйте операции NBT с сущностью:

```json
{
  "time": 60,
  "mergeEntityNBT": [
    { "ref": "marker", "nbt": "{Saddle:1b}" }
  ],
  "modifyEntityNBT": [
    { "ref": "marker", "path": "CustomName", "value": "\"After\"" }
  ],
  "removeEntityNBT": [
    { "ref": "marker", "path": "CustomNameVisible" }
  ]
}
```

`setEntityNBT` также доступен, если вы хотите заменить NBT объекта вместо слияния:

```json
{
  "time": 100,
  "setEntityNBT": [
    { "ref": "marker", "nbt": "{Pos:[0.0d,0.0d,0.0d],Rotation:[0.0f,0.0f],CustomName:\"Reset\"}" }
  ]
}
```

Действия сущности также могут обновлять трансформацию, позу предварительного просмотра игрока и стабильное состояние монтирования без
изменение NBT:

```json
{
  "time": 80,
  "createEntities": [
    { "ref": "cart", "sceneEntityId": "cart", "id": "minecraft:minecart", "x": 1.5, "y": 1.0, "z": 1.5 },
    { "ref": "rider", "sceneEntityId": "rider", "id": "player", "name": "GuideNH", "x": 1.5, "y": 1.0, "z": 1.5, "mount": "cart" }
  ],
  "modifyEntityNBT": [
    { "ref": "rider", "headYaw": 270.0, "leftArmRotation": "-40 0 0" }
  ]
}
```

Чтобы отсоединить или удалить объект временной шкалы, используйте `unmount` или `removeEntities`:

```json
{
  "time": 120,
  "modifyEntityNBT": [
    { "ref": "rider", "unmount": true, "x": 2.5, "y": 1.0, "z": 1.5 }
  ],
  "removeEntities": [
    { "ref": "cart" }
  ]
}
```

Как и операции с плитками, операции с объектами воспроизводятся с самого начала, когда активен
изменяются ключевые кадры, поэтому поиск назад удаляет объекты, созданные Ponder, и воссоздает правильные
состояние целевого тика.

Примечания:

- `ref` определяет, какой объект, принадлежащий Ponder, следует изменить или удалить текущим действием.
- `sceneEntityId` и `mount` определяют стабильные отношения между сущностями. `mount` всегда указывает на
стабильный идентификатор сцены, а не другой `ref`.
- Не рекомендуется полагаться только на необработанный пассажирский NBT для отношений между объектами сцены.
стабильный реестр обеспечивает детерминированное поведение при монтировании и удалении при воспроизведении, перестроении и
импорт/экспорт и обновление предварительного просмотра редактора.

## Затухание аннотации

Аннотации плавно исчезают в течение **5 тактов игры** (250 мс) при каждом активном ключевом кадре.
изменения во время воспроизведения. При поиске или паузе аннотации всегда отображаются полностью непрозрачными.

## Типы аннотаций

Для каждой записи в массиве `annotations` требуется поле `type`. Доступно семь типов.

---

### `diamond`

отображает 3D-ромбовидный маркер в мировой позиции.

```json
{
  "type": "diamond",
  "x": 1.5,
  "y": 2.0,
  "z": 1.5,
  "color": "0xFFFF8800",
  "tooltip": "Click me",
  "alwaysOnTop": false
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `x`, `y`, `z` | плавающее значение | `0.0` | Положение алмазного наконечника в мировом пространстве. |
| `color` | строка | `"0xFF00E000"` | цвет ARGB как `"0xAARRGGBB"`. |
| `tooltip` | строка | `""` | Резервный текст, отображаемый при наведении курсора. |
| `tooltipKey` | строка | `""` | ключ перевода текста при наведении. При разрешении он переопределяет `tooltip`. |
| `alwaysOnTop` | логическое значение | `false` | Если установлено значение true, визуализация осуществляется посредством сплошных блоков. |

---

### `box`

отображает каркасный прямоугольник, выровненный по оси, от `min` до `max`.

```json
{
  "type": "box",
  "minX": 0.0, "minY": 0.0, "minZ": 0.0,
  "maxX": 3.0, "maxY": 2.0, "maxZ": 3.0,
  "color": "0x8800FFFF",
  "lineWidth": 1.5,
  "alwaysOnTop": false
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `minX/Y/Z` | плавающее значение | `0.0` | Минимальный угол. |
| `maxX/Y/Z` | плавающее значение | `1.0` | Максимальный угол. |
| `color` | строка | `"0xFFFFFFFF"` | цвет линии ARGB. |
| `lineWidth` | плавающее значение | по умолчанию | Ширина линии GL. |
| `alwaysOnTop` | логическое значение | `false` | Рендеринг через блоки. |

---

### `block`

отображает каркас вокруг одного целого блока. Это эквивалент Ponder JSON
`<BlockAnnotation pos="x y z">` в обычном `GameScene`.

```json
{
  "type": "block",
  "pos": [1, 0, 1],
  "color": "0xFFFF8800",
  "lineWidth": 1.5,
  "alwaysOnTop": true
}
```

`"type": "blockBox"` и `"type": "block_box"` являются допустимыми псевдонимами.

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `pos` | число[3] или строка. | `[0, 0, 0]` | координата блока как `[x, y, z]` или `"x y z"`. |
| `x`, `y`, `z` | номер | `0` | Альтернативные поля координат блока. Ценности минимальны. |
| `blockX/Y/Z` | целое число | `0` | Поля координат блока в устаревшем стиле. |
| `color` | строка | `"0xFFFFFFFF"` | цвет линии ARGB. |
| `lineWidth` | плавающее значение | по умолчанию | Толщина линии GL. |
| `alwaysOnTop` | логическое значение | `false` | Рендеринг через блоки. |

---

### `line`

отображает сегмент линии или полилинию между мировыми позициями. `points` имеет приоритет над
`fromX/Y/Z` и `toX/Y/Z`, если он содержит как минимум две действительные точки.

```json
{
  "type": "line",
  "fromX": 0.5, "fromY": 0.5, "fromZ": 0.5,
  "toX": 2.5,   "toY": 0.5,   "toZ": 0.5,
  "color": "0xFFFFFF00",
  "arrow": "end",
  "lineWidth": 2.0,
  "alwaysOnTop": true
}
```

Точки полилинии можно записать либо в виде строки, либо в виде массива:

```json
{
  "type": "line",
  "points": [[0.5, 1.2, 0.5], [1.5, 1.8, 1.5], [2.5, 1.2, 2.5]],
  "color": "0xFFFFCC44",
  "arrow": "end"
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `fromX/Y/Z` | плавающее значение | `0.0` | Начальная точка. |
| `toX/Y/Z` | плавающее значение | `1.0` | Конечная точка. |
| `points` | строка или массив. | `null` | Точки ломаной линии. Используйте `"x y z; x y z; ..."` или `[[x,y,z], ...]`. |
| `color` | строка | `"0xFFFFFFFF"` | цвет линии ARGB. |
| `arrow` | строка | `null` | `start` или `end`; пропущенные или недопустимые значения не рисуют стрелку. |
| `lineWidth` | плавающее значение | по умолчанию | Толщина линии GL. |
| `alwaysOnTop` | логическое значение | `false` | Рендеринг через блоки. |

---

### `blockface`

выделяет все грани одного блока полупрозрачным сплошным наложением.

```json
{
  "type": "blockface",
  "pos": [1, 0, 1],
  "color": "0x8833FF33",
  "alwaysOnTop": false
}
```

`"type": "blockFace"` и `"type": "block_face"` являются допустимыми псевдонимами.

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `pos` | число[3] или строка. | `[0, 0, 0]` | координата блока как `[x, y, z]` или `"x y z"`. |
| `x`, `y`, `z` | номер | `0` | Альтернативные поля координат блока. Ценности минимальны. |
| `blockX/Y/Z` | целое число | `0` | Поля координат блока в устаревшем стиле. |
| `color` | строка | `"0x80FFFFFF"` | цвет наложения ARGB. |
| `alwaysOnTop` | логическое значение | `false` | Рендеринг через блоки. |

---

### `text`

отображает всплывающую метку, привязанную к мировому положению. Поле появится над якорем
по умолчанию и соединен с ним короткой вертикальной линией. Текстовое содержимое управляется ключевыми кадрами: используйте
разные записи аннотаций `text` в разных ключевых кадрах для изменения отображаемого текста с течением времени.

```json
{
  "type": "text",
  "x": 1.5,
  "y": 2.5,
  "z": 1.5,
  "text": "Place items here",
  "color": "0xFF44AAFF",
  "connectorSide": "right",
  "connectorOffset": 8,
  "connectorLength": 12
}
```

для фиксированного положения в экранном пространстве, которое не проецируется из мировых координат, используйте
**независимый режим**. Пузырь центрируется горизонтально в сцене и размещается в
`yOffset` пикселей ниже вертикального центра сцены.

```json
{
  "type": "text",
  "text": "Independent label",
  "color": "0xFFFFCC00",
  "backgroundAlpha": 160,
  "independent": true,
  "yOffset": 40
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `x`, `y`, `z` | плавающее значение | `0.0` | Положение привязки в мировом пространстве (игнорируется в независимом режиме). |
| `text` | строка | - | **Обязательно.** Текст для отображения внутри пузырька. |
| `color` | строка | `"0xFFAAAAAA"` | цвет ARGB границы пузырька. |
| `backgroundAlpha` | целое число | `204` | прозрачность фона от `0` (прозрачный) до `255` (непрозрачный). Цвет RGB остается темно-синим по умолчанию. |
| `maxWidth` | целое число | `0` | Если > 0, текст этой ширины переносится в пикселях. Опустите или установите значение `0` для однострочной метки. |
| `independent` | логическое значение | `false` | Если `true`, позиция определяется относительно центра сцены, а не мировой точки. |
| `yOffset` | целое число | `0` | смещение пикселя от вертикального центра сцены (положительное = вниз). Используется с `independent: true`. |
| `connectorSide` | строка | `"bottom"` | `bottom`, `top`, `left`, `right` или `none`. Игнорируется в независимом режиме. |
| `connectorOffset` | целое число | `0` | смещение пикселей вдоль выбранного края пузырька; положительные перемещения вправо для верха/низа и вниз для левого/правого. |
| `connectorLength` | целое число | `6` | Длина соединительной линии в пикселях. `0` скрывает линию, сохраняя при этом расположение сбоку. |
| `hlMinX/Y/Z` | плавающее значение | `0.0` | Минимальный угол необязательного поля выделения, нарисованного рядом с текстовым пузырем. |
| `hlMaxX/Y/Z` | плавающее значение | `1.0` | Максимальный угол дополнительного поля выделения. |
| `highlightColor` | строка | `"0x8000FFAA"` | цвет выделения в формате ARGB. |

если присутствует `hlMinX` (или любая координата `hlMin/Max`), то также присутствует `InWorldBoxAnnotation`.
создан в указанных границах с помощью `highlightColor`. Это полезно для указания на конкретные
блокируйте регионы при их объяснении.

по умолчанию фон представляет собой тёмно-синий пузырь (`#CC0E0E20`), а `backgroundAlpha` управляет его
непрозрачность. В режиме мировой привязки соединительная линия соединяет блок с привязкой. Текст поддерживает
полный встроенный синтаксис форматированного текста GuideNH: форматирование markdown и встроенные теги MDX. Он отображается с помощью
тень.

> **Форматированный текст:** Поле `text` поддерживает ту же встроенную разметку, которая используется на страницах руководства GuideNH:
> `**полужирный**`, `*курсив*`, `~~зачёркнутый~~`, `<Color id="RED">цветной</Color>`,
> `<ItemLink id="minecraft:iron_ingot" />` и все остальные встроенные теги MDX.
> Простые коды формата Minecraft `§` **не** поддерживаются; вместо этого используйте синтаксис MDX.

> аннотация `text` без поля `text` (или пустой строки) игнорируется автоматически.

---

### `input`

отображает значок ввода мыши (левая кнопка, правая кнопка или колесо прокрутки), привязанный к миру.
позиция. Это используется, чтобы намекнуть, что игрок должен выполнить определенное взаимодействие.

```json
{
  "type": "input",
  "x": 0.5,
  "y": 1.5,
  "z": 0.5,
  "inputType": "lmb"
}
```

с необязательным префиксом ключа-модификатора и значком элемента:

```json
{
  "type": "input",
  "x": 0.5,
  "y": 1.5,
  "z": 0.5,
  "inputType": "lmb",
  "modifier": "sneak",
  "item": "minecraft:iron_ingot"
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `x`, `y`, `z` | плавающее значение | `0.0` | Положение привязки в мировом пространстве. |
| `inputType` | строка | `"lmb"` | один из `"lmb"`, `"rmb"` или `"scroll"`. Нечувствителен к регистру. |
| `modifier` | строка | `null` | Дополнительный ключ-модификатор: `"sneak"` или `"ctrl"`. Показывает текст префикса над значком. |
| `item` | строка | `null` | дополнительный идентификатор реестра элементов (например, `"minecraft:iron_ingot"`). Отображает значок элемента слева от значка мыши. Поддерживает формат `"modid:item:meta"` для метазначений. |

Значок представляет собой спрайт 16x16, взятый из `ponder_widgets.png`. Фон коробки полупрозрачный.
темный (`#CC0E0E20`) со светло-синей рамкой (`#80AAAADD`). Если указан `item`, поле
расширяется, чтобы разместить рядом значок элемента и значок мыши.

---

## Формат цвета

цвета представляют собой шестнадцатеричные строки ARGB. И `"0xFFFFFF00"` (с префиксом `0x`), и
`"FFFF00"` (без префикса) принимаются.

- `FF` альфа = полностью непрозрачный
- `80` альфа = прозрачность 50 %.
- `00` альфа = невидимый
- `"0xFF00E000"` — полностью непрозрачный зеленый (цвет ромба по умолчанию)
- `"0x8022CCFF"` — полупрозрачный синий
- `"0xFFAAAAAA"` — светло-серый (рамка текстового пузырька по умолчанию)

## Поведение воспроизведения

### Элементы управления

| Управление | Действие |
|---------|--------|
| **Предыдущий ключевой кадр** | переход к началу предыдущего видимого сегмента ключевого кадра. Скрытые ключевые кадры пропускаются. |
| **Воспроизведение/Пауза** | переключить воспроизведение; перезапускается с начала, если уже завершено. |
| **Перезапуск** | Вернитесь к отметке 0, сбросьте состояние и начните игру. |
| Индикатор выполнения | щелкните или перетащите, чтобы перейти к любой позиции. Поиск всегда приостанавливает воспроизведение. |
| Узлы ключевых кадров | маленькие деления на панели для видимых ключевых кадров; наведите указатель мыши, чтобы увидеть метку и стрелку направления. |

### Исходное состояние

При первом открытии страницы, содержащей `<ImportPonder>`, сцена запускается **с паузой на отметке 0**.
Чтобы начать, нажмите «Воспроизвести».

### Блокировка камеры

Пока воспроизведение **активно** (не приостановлено):
- камера следует по интерполированному пути, определенному ключевыми кадрами.
- Перетаскивание мышью и масштабирование при прокрутке **отключены**.
- Ползунок слоя и ползунок StructureLib **скрыты**.

Когда воспроизведение **приостановлено** или **завершено**:
- полностью интерактивное перетаскивание камеры, масштабирование и управление слоями/StructureLib восстановлены.

### Метки узлов ключевых кадров

При наведении курсора на узел ключевого кадра на индикаторе выполнения:
- узел немного увеличивается, указывая на то, что он наведен.
- если ключевой кадр имеет `label`, он отображается рядом с узлом.
- Скрытые ключевые кадры не создают узлы, которые можно навести, но они по-прежнему применяют свое состояние временной шкалы, когда воспроизведение или поиск достигают их.

### Управление слоями во время воспроизведения

поле `layer` активного ключевого кадра переопределяет фильтр видимого слоя во время воспроизведения:
- `null` (или опущено) -> показать все слои.
- `1`, `2`, `3`, ... -> ограничиться индексом слоя, начинающимся с 1.

### `grinder.snbt`

стандартный файл структуры NBT (созданный с помощью команды `/structure save` или такого инструмента, как

## Примечания

- Индикатор выполнения Ponder отображается над ползунками Layer/StructureLib. Во время воспроизведения
структурные ползунки скрыты, чтобы обеспечить чистоту пользовательского интерфейса; они появляются снова после паузы.
- Интерполяция камеры всегда плавная (с плавным входом/уходом), даже если некоторые ключевые кадры меняют только
подмножество осей камеры. Используйте `cameraEaseTicks` на ключевом кадре, чтобы мгновенно привязать камеру (`0`).
или ослабьте фиксированное количество тиков, прежде чем удерживать целевую позицию.
- аннотации относятся к одному ключевому кадру — они появляются только тогда, когда этот ключевой кадр активен.
(т. е. от тика `time` до тика `time` следующего ключевого кадра). Наложение текстовых аннотаций
плавное исчезновение при изменении ключевого кадра во время воспроизведения.
- Подумайте, аннотации `line` используют тот же модуль визуализации во время выполнения, что и обычный `LineAnnotation`, включая
изгибы полилинии и стрелки начала/конца. Кубы маркеров точек остаются функцией только MDX.
- Подумайте, аннотации `text` используют тот же модуль визуализации во время выполнения, что и обычный `TextAnnotation`, включая
сторона разъема, смещение и длина. Динамический текст основан на ключевых кадрах, а не интерполируется по каждому такту.
- для каждого `<GameScene>` действует только один тег `<ImportPonder>`. Второй тег перезаписывает первый.
- аннотация `text` с пустым или отсутствующим полем `text` автоматически пропускается.
- поле `inputType` по умолчанию имеет значение `"lmb"`, если оно опущено или не распознано.
- `blockChanges` применяются в порядке от первого до текущего ключевого кадра каждый раз, когда
активный ключевой кадр изменяется, поэтому изменение одной и той же позиции в нескольких ключевых кадрах работает правильно.
- операции NBT плитки/объекта используют ту же модель воспроизведения, что и `blockChanges`; их безопасно искать
вперед или назад.
- аннотации `text` с `maxWidth` > 0 переносятся по словам с использованием средства рендеринга ванильных шрифтов;
высота всплывающего окна автоматически регулируется для многострочного текста.
- строки `nbt` в `blockChanges` должны использовать **ключи SNBT без кавычек** (стандартный формат MC 1.7.10).
Ключи в кавычках будут отклонены анализатором. Строковые значения по-прежнему требуют кавычек:
`{id:"minecraft:iron_ingot",Count:8b}`.
- Значения `modifyTileNBT` и `modifyEntityNBT` являются значениями SNBT, а не значениями JSON. Для строки
значение, экранируйте кавычки SNBT внутри JSON: `"value": "\"hello\""`.
