# Совместимость модов

GuideNH поставляется с условной интеграцией для выбранных модов. Каждая интеграция активируется только тогда, когда загружен целевой мод; когда цель отсутствует, связанные теги, индексы и привязки клавиш остаются инертными, а остальная часть руководства продолжает работать.

## Библиотека структуры

Когда StructureLib загружен, GuideNH может импортировать многоблочные предварительные просмотры в `<GameScene>` с помощью `<ImportStructureLib>`. Клиентская команда `/exportStructure structureLib` также может экспортировать эти изображения предварительного просмотра в виде снимков экрана документации в формате PNG. См. [Экспорт структуры](Structure-Export) для получения полной информации по командам, параметрам, специфичным для StructureLib, и соответствующему режиму экспорта `gameScene`.

## Улучшение квестов

Когда загружается [BetterQuesting](https://github.com/GTNewHorizons/BetterQuesting), GuideNH открывает три функции:

1. ключ `quest_ids` page-frontmatter запускает индексацию страниц по идентификатору квеста BetterQuesting.
2. стали доступны два новых тега: `<QuestLink>` (встроенный) и `<QuestCard>` (блочный).
3. Стандартная горячая клавиша «открыть руководство» работает при наведении курсора на квест в графическом интерфейсе BetterQuesting: удерживая клавишу, можно найти наведенный идентификатор квеста и перейти на соответствующую страницу руководства.

### Индексирование страниц по идентификатору квеста

добавьте список `quest_ids` в начало любой страницы руководства, которую вы хотите связать с одним или несколькими квестами:

```yaml
---
navigation:
  title: Stage 2 — Steam Age
quest_ids:
  - 01234567-89ab-cdef-0123-456789abcdef
  - AAAAAAAAAAAAAAAAAAAMug==
---
```

значения могут быть каноническими строками UUID или компактными идентификаторами квестов BetterQuesting Base64. Неверные или пустые записи пропускаются с предупреждением в журнале.

сначала декодируются компактные идентификаторы, затем GuideNH возвращается к каноническому анализу UUID. Это соответствует компактному формату идентификатора квеста BetterQuesting, такому как `AAAAAAAAAAAAAAAAAAAMug==`.

Не указывайте обе кодировки одного и того же квеста в `quest_ids` на одной странице; они нормализуются к одному и тому же внутреннему UUID и будут рассматриваться как дубликаты.

Когда идентификатор квеста индексируется на странице, и `<QuestLink>`, и `<QuestCard>` будут перенаправлять клик на эту страницу руководства вместо непосредственного открытия графического интерфейса квеста BetterQuesting.

### Ссылки из описаний BetterQuesting на страницы GuideNH.

Описания квестов BetterQuesting могут быть связаны с GuideNH с помощью тега `[guide]`. Тег анализируется GuideNH только при загрузке BetterQuesting, а затем отображается через собственное текстовое поле BetterQuesting с поддержкой гиперссылок, поэтому перенос слов BQ, прокрутка и хит-боксы щелчков остаются совместимыми.

используйте идентификатор страницы в качестве цели:

```text
[guide]guidenh:navigation-guide[/guide]
```

Если целевая страница существует, видимый текст ссылки заменяется заголовком этой страницы руководства. Суффикс `.md` не является обязательным, поэтому `guidenh:navigation-guide` и `guidenh:navigation-guide.md` указывают на одну и ту же страницу, если существует страница markdown.

используйте `page=`, если вам нужен собственный видимый текст:

```text
[guide page=guidenh:navigation-guide]Открыть руководство по навигации[/guide]
```

ссылка отображается обычным цветом гиперссылки BetterQuesting с подчеркнутым стилем, при наведении показывает всплывающую подсказку GuideNH и открывает целевую страницу GuideNH при нажатии. Также поддерживаются привязки страниц:

```text
[guide page=guidenh:navigation-guide#navigation-fields]Поля навигации[/guide]
```

### `<QuestLink>` и `<QuestCard>`

Оба тега принимают идентификатор квеста BetterQuesting через `id` и определяют их внешний вид на основе прогресса игрока во время компиляции:

| Состояние | Источник | Рендеринг |
| --- | --- | --- |
| Видимый | квест разблокирован, но не завершен. | кликабельная ссылка, стиль по умолчанию. |
| Завершено | `quest.isComplete(player)` возвращает true | кликабельная ссылка, зеленый цвет, конечный `✓`. |
| Заблокировано | квест существует, но не разблокирован, видимость ≠ СКРЫТЫЙ/СЕКРЕТНЫЙ. | заполнитель, выделенный серым курсивом, не кликабельный. |
| Скрыто | заблокировано, видимость СКРЫТА или СЕКРЕТНА. | темно-серый курсив, подробности квеста не разглашаются. |
| Отсутствует | идентификатор квеста не соответствует ни одному квесту в базе данных. | заполнитель, выделенный красным курсивом. |

Заблокированные, но нескрытые квесты также доступны для кликов. Они используют те же правила навигации, что и видимые и завершенные квесты.

Для видимых/завершенных/заблокированных квестов целью клика является:

- проиндексированная страница руководства, если идентификатор квеста присутствует в `quest_ids` какой-либо страницы.
- в противном случае экран квестов книги квестов BetterQuesting использует собственный поток родительского экрана BetterQuesting.

таблицы атрибутов и встроенные примеры см. в [Справочник тегов](Tags-Reference#questlink)].

### Обработка скрытых квестов

GuideNH никогда не отображает заголовок или описание квеста, видимость которого равна `HIDDEN` или `SECRET`, пока квест все еще заблокирован для игрока. Текст-заполнитель взят из ключа перевода, поэтому пакеты могут локализовать формулировку:

| Ключ перевода | По умолчанию (en_US) |
| --- | --- |
| `guidenh.compat.bq.locked` | `Заблокированный квест` |
| `guidenh.compat.bq.hidden` | `Скрытый квест` |
| `guidenh.compat.bq.missing` | `Неизвестный квест` |
| `guidenh.compat.bq.open_in_guide` | `Открыть в руководстве` |

Заблокированные квесты по-прежнему могут отображать свое описание в виде всплывающей подсказки на `<QuestLink>` и в кликабельном заголовке внутри `<QuestCard>`, поскольку BetterQuesting сам показывает описание во всплывающих подсказках заблокированных квестов. Установите `show_tooltip="false"` (или `showTooltip={false}`), чтобы отключить эту всплывающую подсказку. Скрытые квесты не отображают всплывающую подсказку.

> [!ПРИМЕЧАНИЕ]
> Состояние квеста определяется во время компиляции страницы с использованием прогресса локального игрока. Скомпилированная страница кэшируется для каждого руководства; повторное открытие руководства после завершения или разблокировки квеста приводит к переоценке состояния.

### интеграция горячих клавиш открытого руководства

горячая клавиша открытого руководства по умолчанию (`G`, настраивается в разделе `key.guidenh.open_guide`) получает второй путь активации при загрузке BetterQuesting. Пока графический интерфейс квестовой линии BetterQuesting открыт:

1. наведите курсор на любую кнопку квеста на панели BQ.
2. удерживайте горячую клавишу открытия направляющей.

Если какие-либо зарегистрированные индексы руководства запрашивают идентификатор через `quest_ids`, GuideNH перейдет на соответствующую страницу (или откроет руководство, если оно еще не открыто). Если ни одна страница не индексирует наведенный идентификатор, горячая клавиша ничего не делает — она не возвращается к открытию графического интерфейса квеста BetterQuesting, поскольку BQ уже показывает эту информацию.

Этот путь не зависит от пути всплывающей подсказки к предмету инвентаря, поэтому при наведении курсора на предметы в инвентаре все равно маршрутизируется через существующие поисковые запросы по индексу предметов/руды.

### Поведение при отсутствии BetterQuesting

- `<QuestLink>` и `<QuestCard>` не зарегистрированы, поэтому страницы, которые их используют, возвращаются к стандартному отображению ошибки «неизвестный тег», пока вы не удалите тег.
- записи `quest_ids` по-прежнему анализируются и сохраняются под `additionalProperties`, но ничто их не читает.
- Ветка при наведении на горячую клавишу становится неактивной.
- Ссылки описания BetterQuesting `[guide]...[/guide]` никогда не анализируются, поскольку текстовое поле BetterQuesting и связанные с ним примеси не загружаются.

## Экспорт тегов на сайт

экспортированный сайт отображает теги, поставляемые с GuideNH. Мод, теги которого составлены самостоятельно
`TagCompiler` регистрирует средство визуализации, поэтому его теги также экспортируются, а не отображаются в книге и
исчезает с сайта:

```java
public class MyModSiteTagRenderer implements GuideSiteTagRenderer {

    @Override
    public Set<String> getTagNames() {
        return Set.of("MyMachine");
    }

    @Override
    public String render(GuideSiteTagRenderContext context, MdxJsxElementFields element) {
        String id = element.getAttributeString("id", "");
        return "<div class=\"mymod-machine\">" + GuideSiteGraphRenderer.esc(id) + "</div>";
    }
}
```

```java
GuideNhIntegrationRegistry.global().registerSiteTagRenderer(new MyModSiteTagRenderer());
Guide.builder(id).extension(GuideSiteTagRenderer.EXTENSION_POINT, new MyModSiteTagRenderer()).build();
```

Зарегистрированные средства визуализации запрашиваются перед встроенными, и побеждает тот, который первым вернет разметку, поэтому
средство рендеринга должно обрабатывать только объявленные им теги. Возврат `null` оставляет элемент следующему рендереру.
или во встроенный экспорт. О выдающем рендерере сообщается в журнале и он пропускается, поэтому один сломанный плагин
невозможно выполнить экспорт страницы, которой он не владеет.

контекст содержит экспортируемую страницу и общие службы экспорта: `defaultNamespace`,
`currentPageId`, `templates`, `sceneResolver` и `compiler`, те же значения, что и у встроенных средств визуализации.
с. Написанная вами разметка вставляется на страницу в том виде, в котором она есть, поэтому экранируйте текст с помощью
`GuideSiteGraphRenderer.esc(...)`.

Это означает, что руководство, предназначенное для BetterQuesting, может быть создано один раз и автоматически ухудшаться в средах, где BetterQuesting не установлен.
