# GUI 截图

[English](GUI-Capture.md)

GUI 截图用于框选游戏界面并导出图片，支持透明区域、多选区、录制、定时捕获和批量捕获。

## 打开截图界面

在按键设置的 GuideNH 分类中绑定「打开 GUI / HUD 截图界面」。该按键默认未绑定，可以在打开 GUI 后或正常游玩时使用。

截图工具栏不会出现在导出的图片中。截图界面打开期间由编辑器处理输入，退出后恢复游戏焦点。游玩模式和 GUI 模式分别记忆 HUD 包含设置；游玩模式默认包含 HUD。

## 框选和保存

拖动鼠标创建选区，松开后固定；拖动边角调整大小。使用添加选区按钮，或按住 Ctrl 拖动，创建更多选区。擦除工具用于去除不需要的区域。

吸附支持格子、组件、窗口、HUD 和通知。隐藏控件及被排除的内容层不参与吸附。

默认输出所有选区的外接矩形，并保留原始相对位置。未选中的间隙和擦除区域保持透明，重叠选区不会重复绘制像素。

| 输出布局 | 用途 |
| --- | --- |
| 外接矩形 | 合并选区并保留原始位置 |
| 独立选区 | 分别导出每个选区 |
| 横向排列 | 将选区水平排列 |
| 纵向排列 | 将选区垂直排列 |
| 网格排列 | 将选区排列为网格 |

点击保存图标或按 Enter 保存。设置面板可调整输出目录、尺寸、格式、背景、内容层、吸附和资源预算。

设置中可以按显示像素输入选区 X、Y、宽度和高度，修改加入撤销历史。手柄尺寸同样按显示像素计算。右键默认只重画活动选区，开启「右键重画全部选区」后清除所有选区。横向、纵向和网格排列提供九种单元格对齐方式，不拉伸所选内容。

### 快捷键

| 按键 | 操作 |
| --- | --- |
| Enter | 保存；录制时停止录制 |
| Esc | 关闭面板、取消当前拖动或退出截图 |
| Delete | 删除活动选区 |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做选区编辑 |
| Ctrl+D | 复制活动选区 |
| Ctrl+A | 选择整个 GUI 视口 |
| 方向键 | 移动活动选区 1 个显示像素 |
| Shift+方向键 | 移动 10 个显示像素 |
| Ctrl+方向键 | 整组移动所有选区 |
| 录制时按空格 | 暂停 / 恢复 |

### 内容与显示

GUI、HUD、玩家物品栏、世界、工具提示、NEI、调试信息和 GUI 背景可以分别设置是否参与捕获。默认不包含背后的世界，GUI 内部模型属于 GUI 内容。光标包含设置会保留系统光标图像及其热点。

「反色透明网格」默认开启，使用亮色棋盘格；关闭后使用暗色棋盘格。它只影响预览背景，不改变导出图片。

每次打开截图界面都会显示工具栏。再次按开启快捷键或使用可见性按钮可隐藏、恢复工具栏；隐藏后右下角保留眼睛按钮。「显示选区装饰」和「显示捕获区」分别记忆。设置面板支持 Ctrl+F 搜索、滑条、直接输入数值和平滑滚动。

设置按输出、内容、吸附、交互、录制、定时和批量分组。搜索同时匹配设置名称和分类名称。

### 捕获源与输出质量

设置面板列出可用的捕获源和像素读回器，底部显示实际使用的实现。自动捕获源在关闭世界包含时使用 GUI 独立层，开启时使用最终帧；两者都遵循内容层设置。

可以手动选择捕获源或读回器。切换成功后更新预览，不可用的选项会显示原因。录制和导出使用任务开始时的捕获设置；能力变化导致当前组合不可用时，录制会暂停。

每个轴的输出分辨率不超过源尺寸的 32 倍。支持安全重绘的界面可以导出分块高清图片。自动质量允许在重绘无法匹配预览时使用冻结帧重采样；严格质量会报告不匹配或不支持的组合；兼容输出模式可以放大原生 HUD / GUI 帧。根据界面显示的质量等级和后端能力选择配置。

## 录制和定时捕获

录制支持 GIF、PNG 精灵图和 PNG 帧序列。开始前可设置帧率、时长或最大帧数，录制期间可以暂停、恢复、停止或取消。

录制期间修改的设置用于下一段。「应用到下一段」让当前录制继续使用开始时的设置；「停止并应用」结束当前录制，编码完成后使用修改后的设置。本段捕获源、读回器、输出尺寸、内容和内存预算保持固定。

屏幕、视口或跟随组件变化时，可以选择暂停并等待恢复、结束当前段、结束并开始下一段。下一段等待有效预览和选区。切换屏幕时保留选区矩形，并清除原屏幕的跟踪 ID；同一屏幕内的跟随组件消失时，等待它重新出现。编码失败或取消后不会自动继续。批量录制结束当前段后继续下一个已选批量目标。

PNG 精灵图附带记录帧位置及时间的 JSON 文件。GIF 的透明区域可使用透明阈值或指定底色处理。

录制期间，编辑预览、系统光标和工具提示位置实时更新，即使静态预览设置为冻结也如此。录制预览显示完整捕获源；导出仍保持本段开始时的选区和输出尺寸。暂停或结束后恢复所配置的预览行为。

GIF 透明阈值推荐为 128。阈值 255 会滤掉 alpha 为 253 的原版按钮纹理。任何阈值下完全透明像素都保持透明；需要将半透明内容放在纯色背景上时，使用背景混合。

定时捕获支持延迟、指定本地时刻和按间隔重复执行。游戏失去焦点或目标不可用时，可选择等待、跳过或结束任务。录制队列及临时输出受到设置中的资源预算限制。

失焦、最小化、无捕获界面、游戏暂停和目标消失分别提供独立的定时策略，未覆盖时沿用默认不可用策略。已加载世界的正常游玩界面仍属于有效捕获源。多个条件同时成立时，按停止、跳过、等待的顺序处理。

## 批量捕获

点击「捕获全部」图标，检查目标列表并选择需要捕获的内容，再启动批量任务。

可分别配置可见层、页面和子页面、可达 GUI 范围，以及提供器、弹窗处理、变体、导航超时、目标上限和恢复行为。捕获会等待界面、页面、物品栏同步及滚动位置就绪；持续动画不会阻止已经就绪的目标。

部分目标需要模组适配或服务端截图协议。不可用目标和失败结果会显示具体原因。服务端范围填写当前维度中两个包含边界的端点：`x,y,z:x,y,z`；留空则使用半径，只枚举范围内已加载的目标。

### 支持的目标

- 玩家持有的成书和书与笔提供只读预览，开启页面范围后遍历其余书页。
- 单箱子、双箱子及燃烧或闲置熔炉提供独立预览。
- 已加载的成年村民、驯服成年马及箱子、漏斗矿车需要服务端支持，并遵守容器归属和距离限制。
- Guide 页面使用独立只读视图，保留原编辑器、草稿、文本选择和撤销历史。

### 联系表和滚动长图

联系表将批量结果整理为分页缩略图，可按提供器分组。

滚动长图支持 GuideNH、NEI、MUI1、MUI2 和 BetterQuesting 界面。切片按文档位置合成，固定控件保留在原始视口截图中。MUI1 和 MUI2 支持嵌套页签及横纵向滚动；MUI2 也会发现打开页签后才创建的组件，展开嵌套滚动区域，并等待滚动动画稳定。它的长图不包含滚动条和边缘阴影；结束后恢复原设置和滚动位置。展开预算不足时保留未处理目标的数量，并将结果标为部分完成。

### BetterQuesting 页面

`betterquesting_pages` 可从任务首页、章节阅读器或任务详情页开始，遍历可进入的章节和可见任务，并捕获描述、任务、奖励及地图内容。开始导航前应关闭模态弹窗。

隐藏内容被排除，锁定的可见章节标记为不可用。地图范围由实际组件边界决定，支持负坐标。任务结束后恢复章节、书签、缩放和滚动状态。捕获不会领取任务、发放奖励或开启编辑模式。

### Thaumcraft 页面

`thaumcraft_pages` 可从研究浏览器或配方书开始，列出可进入的类别和可见研究，并捕获已完成研究的实际双页内容。

隐藏研究被排除，未完成的可见研究标记为不可用。类别地图按可见研究边界和原生平移限制分片，地图区为 224 × 196。结束后恢复类别、地图位置和配方历史；捕获不会解锁研究或消耗研究资源。

### 输出文件

`batch.json` 记录各目标的捕获结果、恢复状态和合成输出。分组页面预览为每个目标或独立选区生成一帧带名称的预览，可导出 GIF、精灵图或已注册的动画格式。预览尺寸使用“联系表／页面预览尺寸”，每页时长按毫秒设置；原始截图保留所选分辨率。分组优先使用目标提供的 `mod_id`，其次使用目标的捕获 `provider`，最后使用批量提供器 ID；关闭分组时合为一组。精灵图输入按 `animation.json` 的首帧矩形取图。滚动长图包含 `scroll.png` 与 `scroll.json`，后者记录裁剪、目标矩形、像素比例及覆盖范围。

达到目标上限或缺少切片时，结果标记为部分完成并保留未覆盖范围。联系表和长图共享批量任务的剩余磁盘预算；取消或失败时清理未发布的临时输出。每组页面输出附带 `pages.json`，记录目标 ID、源文件、源矩形和页面时序；GIF 位于 `pages.gif`，目录编码器输出到 `animation` 子目录。

## 开发者接入

捕获接口分别支持几何提供器、GUI 渲染器、捕获源、像素读回器、批量提供器和输出编码器。

`CaptureLayoutOptions` 携带 `CaptureAlignment`，三参数及四参数构造器使用 `TOP_LEFT`。`CaptureRecordingOptions` 携带 `CaptureTargetChangePolicy`，十四参数构造器使用 `PAUSE`。`CaptureSetting` 明确携带设置分类；`withSection` 可以选择分类，同时保留当前值、选项和滑条。

| 接口 | 用途 |
| --- | --- |
| `CaptureRegistry.registerSource` | 注册 `CaptureSourceProvider` |
| `CaptureRegistry.registerReader` | 注册 `CapturePixelReaderProvider` |
| `CaptureRegistry.registerPhaseListener` | 注册阶段监听器 |
| `CaptureRegistry.registerExporter` | 注册静态图片 `CaptureExporter` |
| `CaptureRegistry.registerAnimationExporter` | 注册 `CaptureAnimationExporter` |
| `CaptureRuntime.selectSource` / `selectReader` | 按 ID 选择实现 |
| `CaptureBatchReadiness` | 声明批量目标的准备状态 |
| `CaptureBatchNavigator.scrollGeometry` | 提供 `CaptureScrollGeometry` |
| `StandaloneContainerScreen` | 为独立生命周期的容器界面提供 `updateStandaloneScreen` |

注册和实现选择在客户端线程进行；选择实现时不能有活动捕获任务。提供器报告可用性时不应分配缓冲区，资源上下文键应包含屏幕、渲染上下文及能力代次。自动选择优先使用最后注册的可用提供器。

批量宿主通过 `CaptureBatchHost.requestFrame` 使上一导航状态的像素失效。异步宿主在捕获像素时调用 `CaptureBatchEngine.framePrepared`，读回完成后调用 `frameReady`，取消时调用 `discardFrame`。就绪检查保持只读；准备帧会一并携带就绪状态、捕获矩形和滚动几何。

### 输出编码器

在客户端线程通过 `CaptureRuntime.registry()` 注册编码器。格式 ID 以字母开头，只包含字母、数字、下划线和连字符，同时用作文件扩展名；`regions` 为保留值。每种格式只能归属静态图片或动画之一。同格式的新编码器替换后续任务的实现，已经开始的导出或录制保留原编码器实例。

`CaptureFormatCatalog` 为设置模型提供当前格式列表及动画分类。`CaptureOptions.format` 保存所选 ID，五参数和六参数构造器默认 PNG。静态格式可用于保存、定时、批量和独立选区导出；选择静态格式时，录制操作默认使用 GIF。

需要分块高倍输出时，实现 `CaptureRowExporter`。导出线程持有并关闭 `CaptureRows`，编码器只读取，不保留或关闭流。严格高倍输出要求支持逐行编码；自动质量在缺少该能力时使用兼容帧导出。独立选区编码器收到该选区、擦除区域、准确输出尺寸和剩余磁盘预算，必须保留尺寸并遵循预算。`CaptureRegionWriter` 可扩展逐行选区编码，并共用清单和裁剪逻辑。

### 捕获阶段与资源生命周期

`CaptureSource.capturePhase` 指定捕获阶段，默认使用 `FRAME_READY`。

| 阶段 | 含义 |
| --- | --- |
| `WORLD_READY` | 世界及 shader-group 绘制完成后 |
| `GUI_BEGIN` | GUI 开始绘制时 |
| `GUI_END` | 屏幕渲染器返回后 |
| `FRAME_READY` | 后置层和主帧缓冲 blit 完成、提交呈现之前 |

捕获源接收配对的 GUI 开始和完成回调，并返回视口尺寸的像素数据。`CaptureContext` 携带当前阶段和渲染状态；`CaptureFrameIdentity` 记录后端、选项、实际内容、读回目标及四阶段快照。批量输出可通过 `capture.source`、`capture.reader` 和帧身份字段保留来源信息。

`CapturePixelReader.enqueue` 和 `CaptureLayerSource.enqueueGuiLayer` 返回由调用方持有的 `CaptureReadback`。在提交时的渲染线程轮询、消费和释放句柄；每个句柄只能消费一次，取消时必须关闭。读回器返回直通 ARGB，并在会话关闭时释放资源。

快照已经应用内容过滤时，通过 `filtersContent()` 声明。批量准备代次应描述已就绪内容；可使用 `CaptureBatchReadiness.viewRevision(context.capture())` 作为屏幕和视口的基础代次。

### 后端与兼容性

Angelica 为活动 `RenderBackend` 注册 `angelica` 读回器，自动选择会优先使用它。底层回调应填充从下到上的 ARGB 数值，并恢复修改过的像素打包参数及缓冲绑定。`CaptureBufferPixelReader` 提供共享的缓冲复用、行方向处理和 Alpha 转换。

自定义着色器或无法由通用重绘支持的路径需要独立快照提供器。可用性和输出质量取决于模组版本及后端；截图工具不会自动修改渲染后端或着色器偏好。
