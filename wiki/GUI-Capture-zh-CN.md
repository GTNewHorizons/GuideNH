# GUI 截图

[English](GUI-Capture.md)

GUI 截图允许在游戏界面中创建选区，并将指定内容导出为图片。支持多选区、透明区域、独立选区导出、录制、定时捕获和批量捕获。

在按键设置的 GuideNH 分类中绑定「打开 GUI / HUD 截图界面」，该按键默认未绑定。打开 GUI 后或正常游玩时按下绑定键即可进入截图覆盖层。工具栏和设置面板采用半透明布局，导出图片不包含截图工具本身。

游玩捕获保持游戏实际没有打开 GUI，使模组 HUD 和通知继续遵循原来的显示条件。编辑器接管输入，退出后恢复游玩焦点。游玩模式的 HUD 包含设置默认开启，与 GUI 模式分开记忆；渲染 tick 末尾的覆盖层和成就提示同样遵循 HUD 开关。冻结预览保留原始像素和对应磁吸目标。

## 框选和保存

拖动鼠标创建选区，松开后固定；拖动选区边角可调整大小。吸附支持格子、组件、窗口、HUD 和通知。除组件元数据外，还通过文字和绘制边界投影、可见像素区域补充目标，自定义 HUD 无需逐个模组适配即可提供磁吸区域，并可显示悬停目标的类名。

使用添加选区按钮，或按住 Ctrl 拖动，可以创建多个选区。使用擦除工具清除不需要的区域。

默认将所有正选区合并为外接矩形输出，并保留原始位置。未选中的间隙和擦除区域在预览及导出结果中保持透明。重叠选区不会重复绘制像素。

支持以下输出布局：
- 外接矩形：将所有正选区合并输出，保留原始相对位置。
- 独立选区：分别导出每个选区。
- 横向排列：将选区水平排列。
- 纵向排列：将选区垂直排列。
- 网格排列：将选区排列为网格。

点击保存图标或按 Enter 保存。设置面板可配置输出尺寸、格式、背景、内容层、吸附方式、输出目录和资源预算。

默认不包含背后的世界，GUI 内部模型仍属于 GUI 内容。工具提示、调试信息、NEI 和 GUI 背景均可独立配置。

### 捕获源与像素读回器

捕获源决定截图从哪个渲染阶段获取画面，像素读回器负责将捕获缓冲区转换为可导出的像素数据。设置面板会显示已注册的提供器及其可用状态。

捕获源支持自动选择和手动指定：
- 自动源在关闭世界包含时使用 GUI 独立层，开启时使用不透明的最终帧。
- GUI 独立层和最终帧均遵循内容层设置。
- 显式选择最终帧时，也可以关闭世界包含。
- 不可用的提供器会显示具体原因。

成功切换捕获源或读回器后，预览会更新；选择失败时保留当前预览。设置面板底部会显示实际使用的实现。

录制和导出期间会固定使用任务开始时的捕获源、读回器及内容快照，避免任务执行过程中配置变化影响输出。提供器能力发生变化时，空闲资源会根据新能力重新创建，受影响的录制任务会暂停。

### 快捷键

| 按键 | 操作 |
| --- | --- |
| Enter | 保存；录制时停止录制 |
| Esc | 关闭面板、取消当前拖动或退出截图 |
| Delete | 删除活动选区 |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做选区编辑 |
| Ctrl+D | 复制活动选区 |
| Ctrl+A | 选择整个 GUI 视口 |
| 方向键 | 移动活动选区 1 个 GUI 像素 |
| Shift+方向键 | 移动 10 个 GUI 像素 |
| Ctrl+方向键 | 调整活动选区大小 |
| 录制时按空格 | 暂停 / 恢复 |

每个轴的输出分辨率不超过源尺寸的 32 倍。支持重绘的 GUI 使用分块处理大图。

对于无法安全重绘的捕获源，是否允许使用原生截图或重采样取决于质量策略。选择质量策略时，可以查看界面显示的质量等级和后端能力。

### 内容与显示设置

GUI、HUD、玩家物品栏、世界和工具提示可以分别设置是否参与捕获。

“反色透明网格”默认勾选，使用亮色透明背景棋盘格；取消勾选使用暗色网格。此选项只改变预览背景，不改变 GUI 光照或导出图像。

隐藏控件和被排除的内容层不会参与吸附。冻结的工具提示沿用实际绘制时采集的边界。

光标包含功能通过 Windows 或 X11 原生 API 读取系统当前光标图像及热点。分块 GUI 快照同样使用系统光标和物品栏遮罩。

高分辨率 HUD 的安全重绘受到质量策略限制：
- 严格质量模式会拒绝不支持安全重绘的组合。
- 兼容输出模式会放大完整的原生 HUD/GUI 帧。

### 覆盖层控制

使用可见性按钮可以隐藏工具栏，右下角按钮可重新显示工具栏。

截图界面的显示/隐藏快捷键默认为 F6，可以在按键设置中重新绑定。截图已经开启时，原开启快捷键也可以用于切换界面。

其他显示控制包括：
- 暂时隐藏选区装饰。
- 显示选区遮罩下方的完整捕获源。
- 通过设置面板调整截图参数。

设置面板支持 Ctrl+F 搜索、平滑滚动、数值滑条和直接输入数值。

## 录制和定时

录制支持以下输出格式：
- GIF
- PNG 精灵图
- PNG 帧序列

开始录制前，可以设置帧率、录制时长或最大帧数。覆盖层提供暂停、恢复、停止和取消操作。

PNG 精灵图会附带 JSON 文件，记录每帧的矩形位置和时间信息。GIF 可以根据配置使用透明阈值或指定底色处理透明区域。

### 定时捕获

定时捕获支持：
- 延迟捕获：等待指定时间后开始捕获。
- 指定时刻：在本地指定时间执行捕获。
- 重复捕获：按照设定间隔重复执行。

当游戏失去焦点或目标 GUI 不可用时，可以配置以下行为：
- 等待：等待目标重新可用。
- 跳过：跳过当前捕获。
- 结束：终止当前任务。

录制队列和临时输出均受资源预算限制，可以在设置中调整。

## 批量捕获

点击「捕获全部」图标进入批量捕获界面。系统会先扫描并列出可用目标，用户可以检查目标列表并选择需要捕获的内容。

批量捕获支持独立配置以下范围：
- 可见层：决定参与捕获的界面内容层。
- 页面：决定需要遍历的页面和子页面。
- 可达 GUI：决定允许导航到的 GUI 目标。

提供器、弹窗处理、变体、导航超时、目标上限和恢复行为均可配置。

部分目标需要特定的模组适配或服务端支持。例如，可达服务端容器需要截图协议及合法的服务端上下文。不可用目标和捕获失败会显示具体原因。

### 联系表

开启联系表后，可以将批量捕获结果整理为分页缩略图，并选择是否按照提供器分组。

联系表使用批量任务的剩余磁盘预算。任务取消或失败时，未发布的临时文件会被清理。

### 滚动长图

开启滚动长图后，支持的 GuideNH、NEI、MUI1 和 BetterQuesting 界面可以通过滚动切片合成为完整图片。

滚动长图按照文档位置合成，而不是简单地将截图首尾拼接。

MUI1 支持：
- 嵌套页签。
- 横向和纵向滚动控件。
- 列表内容。

批量捕获结束后会恢复原来的页签和滚动位置。

固定控件保留在独立的原始视口截图中。相邻切片重叠的部分由最后一个切片直接覆盖，不会重复叠加透明度。

### BetterQuesting 页面捕获

`betterquesting_pages` 提供器支持从以下位置开始遍历：
- 任务首页。
- 章节阅读器。
- 任务详情页。

提供器会遍历可进入的章节和可见任务，并捕获描述、任务、奖励及地图的滚动内容。

地图输出根据实际组件边界计算，支持负坐标，不会将仅供手动拖动的大面积空白区域纳入输出。

捕获规则：
- 隐藏内容不会进入批量捕获目录。
- 导航被锁定的可见章节会明确标记为不可用。
- 目标限制或缺失切片会产生部分完成结果。

恢复时会保留原章节、书签、缩放、滚动位置及任务滚动缓存，不会清空无关缓存。

捕获过程不会检测或领取任务、发放奖励，也不会开启编辑模式。

页面导航前需要关闭 BetterQuesting 的模态弹窗。

### Thaumcraft 页面捕获

`thaumcraft_pages` 提供器支持从原生研究浏览器或配方书开始遍历。

提供器会列出可进入的类别及可见研究，并通过原生配方书构造器打开已完成研究。

研究页面按照原生构造流程处理隐藏文本过滤和动态要素页，再展开实际双页内容。

捕获规则：
- 未完成的可见研究会显示为不可用。
- 隐藏研究会被排除。
- 类别地图切片根据可见研究边界、原生平移限制及裁剪后的 224×196 地图区计算。
- 长图会排除固定控件。
- 固定控件保留在类别视口截图中。

目标数量受到批量捕获上限限制。达到上限时会明确报告剩余地图切片；缺失覆盖区域会保留在部分完成结果中。

恢复时会保留原类别、地图插值和目标位置、浏览器记忆位置及配方历史。

捕获不会解锁研究，也不会消耗研究资源。

### 批量输出结构

`batch.json` 记录每个目标的捕获结果、恢复状态和合成输出信息。

每份滚动长图包含：
- `scroll.png`：合成后的长图。
- `scroll.json`：记录来源裁剪、目标矩形、像素比例和覆盖范围。

达到目标上限或缺少切片时，会生成明确的部分完成结果，并保留未覆盖区域的信息。

联系表和滚动长图共享批量任务的剩余磁盘预算。任务取消或失败时，未发布的临时合成文件会被清理。

## 开发者接入

GUI 截图提供可扩展的捕获接口，可分别注册几何提供器、GUI 渲染器、捕获源、像素读回器、批量提供器和输出编码器。

### 捕获源与读回器注册

使用 `CaptureRegistry.registerSource` 注册 `CaptureSourceProvider`，使用 `registerReader` 注册 `CapturePixelReaderProvider`。

提供器在报告可用性时不应分配捕获缓冲区，捕获管线会在实际需要时打开资源。

自动选择优先使用最后注册的可用提供器。

上下文键需要包含资源所依赖的屏幕、渲染上下文或能力代次，以便在上下文变化时正确管理资源。

捕获源会收到配对的 GUI 开始和完成回调。

### 捕获阶段

`CaptureSource.capturePhase` 用于指定捕获源执行捕获的阶段：

| 阶段 | 含义 |
| --- | --- |
| `WORLD_READY` | 世界及 shader-group 绘制完成后 |
| `GUI_BEGIN` | GUI 开始绘制时 |
| `GUI_END` | 屏幕渲染器返回后 |
| `FRAME_READY` | 后置层和主帧缓冲 blit 完成、提交呈现之前 |

默认使用 `FRAME_READY`。

通用 `capture` 回调保留旧的完整帧回调兼容。

捕获源在指定阶段返回视口尺寸的像素数据。提前捕获的帧由运行时持有，直到最终呈现阶段。不重定向 GUI 绘制的捕获源同样会收到完成回调。

`CapturePhaseListener` 可以观察四个阶段的边界。通过 `CaptureRegistry.registerPhaseListener` 在客户端线程注册监听器。

`CaptureContext` 携带当前阶段及观测到的渲染状态。

GUI 独立层包含 RenderTick End 后置绘制，最终帧源读取呈现 back buffer。

`CaptureFrameIdentity.readback` 记录捕获阶段、实际读回目标及四阶段不可变快照。

### 捕获源与读回器选择

在客户端线程且没有活动捕获任务时，可以通过以下接口按 ID 选择实现：

- `CaptureRuntime.selectSource`
- `CaptureRuntime.selectReader`

选择失败时保留当前预览；选择成功后会使旧预览失效并请求新帧。

读回器接收明确的源 Alpha 模式，返回直通 ARGB 帧，并在会话关闭时释放资源。

原生 GUI 层和分块导出使用相同的读回接口。

### 捕获数据与身份记录

`CaptureFrameIdentity` 用于描述实际捕获帧，包括：
- 实际使用的捕获后端。
- 请求的捕获选项。
- 实际捕获的内容。
- 捕获阶段。
- 实际读回目标。
- 四阶段不可变快照。

导出选项会固定实际使用的实现 ID，避免任务执行期间配置变化导致捕获结果不一致。

批量捕获结果通过 `capture.source` 和 `capture.reader` 记录捕获来源，包括保留的可见层帧。

批量数据还可以记录以下信息：

- `capture.frame`
- `capture.phase`
- `capture.phases`
- `capture.backend`
- `capture.opengl`
- 帧缓冲及缓冲编号
- viewport
- shadow-pass 状态

### GUI 导航与滚动捕获

客户端 GUI 导航使用 Forge 初始化后实际打开的屏幕，支持 Angelica 视频设置等同步屏幕替换。

打开操作被取消时会明确报告失败。

滚动导航器可以通过 `CaptureBatchNavigator.scrollGeometry` 返回 `CaptureScrollGeometry`，供编码模块读取导出帧使用。编码模块不需要依赖具体模组 GUI 的实现。

继承容器界面但拥有独立更新生命周期的界面，可以实现 `StandaloneContainerScreen`，并提供 `updateStandaloneScreen`。

### Angelica 后端适配

Angelica 为当前 `RenderBackend` 注册 `angelica` 像素读回器，通过后端 API 读取打包像素，并在转换为直通 ARGB 前恢复像素打包参数和缓冲绑定。

加载 Angelica 时，自动读回会优先使用对应的后端实现。

在 SDL GPU 下显式选择 `opengl` 读回器时，如果该实现不可用，界面会显示具体原因。

捕获源的资源键同时保留原捕获源的上下文键与实际后端身份。

原生和后端读回器通过 `CaptureBufferPixelReader` 共享缓冲复用、行方向处理及 Alpha 转换逻辑。

后端回调负责填充从下到上的 ARGB 数值，并恢复其修改的渲染状态。

### 兼容性说明

捕获功能的可用性取决于实际模组版本和渲染后端。

不同捕获源、读回器和 GUI 适配器可能具有不同的质量等级及能力限制。用户应根据设置面板显示的可用性和质量信息选择合适的配置。

截图工具不会自动修改渲染后端或着色器偏好。
